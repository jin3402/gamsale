## 1. CheapShark Rate Limit

### 증상
- "API 요청이 너무 많다" / 429
- Steam·Epic 목록이 간헐적으로 비거나 실패

### 원인
- 할인 목록(`/deals`) 외에 역대 최저 확인용 `/games`를 다수 호출
- 플랫폼 전환·전체 뷰에서 호출이 중첩

### 해결
- 스토어당 **최대 1페이지**만 호출
- **약 10분 세션 캐시**
- 429 시 fail-fast
- 역대 최저 배지/정렬에 쓰이던 `/games` enrichment **제거**
- 관련: `cheapSharkClient.ts`, `cheapSharkRequest.ts`, `epicClient.ts`

### 교훈
- 무료 공개 API는 호출 예산부터 설계할 것
- "있으면 좋은" 메타데이터는 rate limit과 트레이드오프

## 2. AIT 업로드 — 동일 버전 거부

### 증상
- 콘솔 업로드 시 같은 버전이라 거부

### 원인
- 배포 버전은 `package.json`만이 아니라 **`public/app.json`의 `version`** 을 씀

### 해결
- `public/app.json` + `package.json` 버전을 함께 올림 (예: `1.0.1` → `1.0.2`)
- 빌드 후 `.ait`에 버전이 임베드되는지 확인

### 체크리스트
- [ ] `public/app.json` version 변경
- [ ] `package.json` version 동기화
- [ ] `npm run build` 후 재업로드

## 4. 닌텐도 · PlayStation — 업로드 후 목록 없음

### 증상
- 로컬 `npm run dev` 에서는 보임
- `.ait` 업로드(토스 WebView) 후 Nintendo / PlayStation 비어 있음
- Steam/Epic은 대체로 정상

### 원인
1. **개발**: Vite 프록시 (`/api/nintendo-store`, `/api/ps-graphql`) → CORS 우회
2. **프로덕션**: 스토어를 **브라우저 Origin에서 직접 fetch** → CORS 차단
3. CheapShark는 `Access-Control-Allow-Origin: *` 라서 통과
4. 부가: 닌텐도 KR price API가 인기 NSUID에 `not_found`를 자주 반환, HTML 파싱·필터에 의존

### 해결 — 빌드 타임 스냅샷
- `scripts/generate-deal-snapshots.mjs`
- `npm run snapshot:deals` / `prebuild` 에서 스토어를 **Node(서버측)** 로 fetch
- 결과를 `src/features/game-deals/api/snapshots/consoleDeals.ts` 에 저장
- 런타임:
  - **DEV / 프록시 ON**: 실시간
  - **프로덕션**: 스냅샷 사용 (`consoleSnapshots.ts` + 각 Client)

```
로컬(dev + proxy)  → 실시간 API
토스 WebView       → 번들된 스냅샷
빌드 직전          → snapshot:deals 로 스냅샷 갱신
```

### PlayStation 특이사항
- 구 HTML/검색 방식 대신 GraphQL `categoryGridRetrieve` 사용
- Hash / Category ID는 `config.ts` 에 상수화
- Vite 프록시: `/api/ps-graphql` → `https://web.np.playstation.com`

### 제한
- 스냅샷은 **빌드 시점** 데이터 (실시간성 ↓)
- 완전 실시간은 파트너 백엔드 / Cloudflare Worker 등 **서버 프록시** 필요

## 5. Xbox — 계속 안 나옴

### 증상
- Xbox 칩 선택 시 목록 비어 있음 (업로드/WebView에서 특히)

### 원인 A — CORS
- `storeedgefd.dsx.mp.microsoft.com` 응답에 `Access-Control-Allow-Origin` 없음
- 문서/가정과 달리 **Xbox도 WebView 직접 호출 불가**
- → 닌텐도/PS와 동일하게 **스냅샷**으로 해결 (`xbox` 필드 추가)

### 원인 B — 가격 파싱 (Game Pass)
- 카드 `Price` 가 종종 `0` (Game Pass "무료" 표시)
- `StrikethroughPrice` 가 zero-width 문자만 있는 경우 많음
- 실제 유료 할인은 `SkusSummary[].MSRP` + `SalePrices` (`BadgeId: default`) 에 있음

### 해결
1. `resolvePaidPrices()` 로 SkusSummary 우선 파싱
2. 인기 리뷰 필터 제거 / 최소 할인율 완화(10%)
3. 검색 쿼리: 프랜차이즈 + 장르 + sale/deal 혼합
4. 프로덕션: `getXboxSnapshotDeals()`

### 검증 메모 (2026-07-19)
- Node에서 프랜차이즈 검색 시 할인 100개+ 수집 가능
- 브라우저 Origin에서는 CORS로 실패 → 스냅샷 필수

## 6. 위시리스트 공유 링크

### 증상
- 공유 시 CheapShark redirect URL로 연결됨

### 원인
- Steam/Epic `mapDeal` 이 `https://www.cheapshark.com/redirect?dealID=...` 사용

### 해결
- `storeUrl.ts`
  - Steam: `store.steampowered.com/app/{id}` 또는 검색
  - Epic: Epic Store browse 검색
  - Xbox / PS / Nintendo: 상품 URL 또는 스토어 검색
- 공유 시 `resolveStoreUrl()` 사용 (`formatWishlist.ts`)
- 기존 찜 데이터 로드 시 CheapShark URL 보정 (`wishlistStorage.ts`)

## 7. 전면형(Interstitial) 광고

### 증상
- 칩을 눌러도 전면 광고가 안 뜸

### 원인
1. 트리거가 **`전체` → 다른 플랫폼`일 때만** 이었음
2. `show()` 가 **로드 완료 전**이면 `false` 반환 후 무시
3. 로컬 브라우저에서는 `loadFullScreenAd.isSupported() === false` (토스 앱/샌드박스에서만 동작)

### 해결
- 플랫폼 칩이 **실제로 바뀔 때마다** `showInterstitial()`
- 미로드 시 `pendingShow` → `loaded` 이벤트에서 즉시 show
- 패턴: `load → show → (dismiss) → load`
- 라이브 ID: `adIds.ts` 의 `LIVE_INTERSTITIAL_AD_GROUP_ID`

### 참고
- 토스 앱 버전 / ATT(iOS) / 광고 그룹 설정이 안 되면 로드 실패 가능
- 개발 중 테스트 ID: `ait-ad-test-interstitial-id` (정책상 실서비스 ID로 테스트 금지 권고)

## 11. 빌드·스냅샷 운영 가이드

### 스크립트
```bash
npm run snapshot:deals   # 스냅샷만 갱신
npm run build            # prebuild → snapshot → ait build
```

### 스냅샷 대상
| 플랫폼 | 소스 | 프로덕션 |
|--------|------|----------|
| Steam | CheapShark (CORS OK) | 실시간 |
| Epic | CheapShark (CORS OK) | 실시간 |
| Xbox | Microsoft Store search | **스냅샷** |
| PlayStation | PS GraphQL | **스냅샷** |
| Nintendo KR | eShop HTML (+선택 price API) | **스냅샷** |

### 주의
- 스냅샷 생성은 **네트워크 필요** (샌드박스/오프라인 빌드 시 이전 스냅샷 유지 로직 있음)
- 환율은 빌드 시점 `VITE_USD_KRW_RATE` 또는 기본값으로 KRW 환산 고정
